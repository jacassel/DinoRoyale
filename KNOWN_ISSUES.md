# Known issues

- Version 0.5 expands the roster to six. The owner confirms successful multiplayer across multiple different networks on the prior release. This update has separate-process local regression evidence, not a new two-PC WAN session; see VERSION05_TEST_REPORT.md. Both peers must update to compatibility **2026100505**. The prior QA2 EOS URL and typed compatibility repairs remain intact.
- The original Refresh timeout was not reproduced in the September 26 physical test: the correct host appeared. This does not establish that intermittent provider timeouts are eliminated. Restart after a timed-out online operation.
- Distributable builds exclude configured credentials. Copy the existing `OnlineServices.ini` to `Windows/DinosaurBattle/OnlineServices.ini` on each PC. No Epic portal, firewall or security settings were changed by the agent. Windows Security displayed its network-permission dialog during Version 0.5 native inspection; it was left for the owner to handle, as requested.
- The prior release's largest test used ten real packaged processes on one PC over development loopback sockets. Its headless simulation rate is not rendering performance or WAN evidence. Version 0.3 includes four-process sessions and ten-combatant configurations; exact per-candidate results are in TEST_LOG.md. Bounded runs do not establish long-session stability.
- Combat is server authoritative without historical hit rewind. Host advantage and delayed hit feedback are expected under latency; competitive balance needs real human internet playtesting. Injected delays and 2% loss passed the recorded correctness checks.
- There is no host migration: host departure returns guests to the menu. A timed-out online operation requires restarting before retrying online. Offline play remains available.
- The browser currently displays up to seven compatible results at once. Large public populations, account restrictions and Epic overlay behavior need live EOS validation. No production anti-cheat, dedicated hosting, voice chat or Steam integration is included.

- Combat balance is based on bounded AI trials, not competitive human playtesting. Retreats can produce unresolved encounters; first scoring deaths and subsequent counterkills are recorded separately.
- Animations switch explicit clips without full blending or foot placement. Original models remain procedural; joints, body overlap during close combat and sliding need further polish.
- Creature sounds are cinematic designs layered from credited CC0 recordings. The agent could verify timing, playback, levels and clipping but could not directly listen in this session; human listening remains necessary to judge realism and the final mix.
- All six selection portraits use the actual models. The new animals have original procedural meshes and explicit animation clips; close-range limb sliding and body intersections remain visible in some poses.
- Prior Version 0.3 performance measurements are historical in `PERFORMANCE_REPORT.md`; they are not measurements of the expanded roster. Current Version 0.5 measurements belong in `VERSION05_TEST_REPORT.md`. Results vary by PC; the ordinary 60 FPS cap is unchanged. Timing samples can miss individual spikes and are not a full profiler trace.
- Carcasses persist during the current game session, not across quitting/reloading. Frozen corpses are grounded approximations without ragdoll physics; reduced detail and slope intersections can be visible.
- Long-session corpse accumulation and hunger pacing still need human playtesting beyond the bounded world runs. Version 0.5's four three-minute endurance scenarios reached 61 accumulated carcasses without failed AI paths or below-terrain actors. Reduced LOD and distance culling limit their cost.
- Map visibility is sight/noise based; AI target acquisition still uses the existing tactical/proximity system and is not a complete stealth simulation.
- The visual modernization adds textured skin, differentiated surfaces, layered water and fuller foliage, but anatomy, fern silhouettes, large boulders and distant terrain still reveal their procedural origins. This is not photorealistic reference-level art. Water uses screen-space reflections, which can lose reflected objects near screen edges; it has no physical waves or wake simulation. The runtime-generated editor level appears sparse before Play.
- Public source and the verified playable ZIP are published at https://github.com/jacassel/DinoRoyale. Local Git and playable recovery checkpoints remain intact. Use the release-specific manifest and current repository documentation to identify the tested build.
- The prior release's close-range Computer Use testing combined native mouse attacks/menus with bridge-held controls; see historical NATIVE_PLAYTEST_REPORT.md. Version 0.5 uses rendered mapped-input tests and screenshot inspection. Its Windows Security dialog limited foreground native mouse/keyboard review; this is not continuous human balance or animation-feel assessment.

Final launch/package status and test results are recorded in TEST_LOG.md.
